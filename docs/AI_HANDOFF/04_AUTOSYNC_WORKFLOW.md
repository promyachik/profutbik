# AUTOSYNC WORKFLOW — обязательный способ взаимодействия

## Формат каждого технического решения

- Один ZIP, совместимый с AutoSync.
- В корне ZIP — BAT для двойного щелчка.
- Никакой внешней папки-обёртки над BAT.
- BAT вызывает вложенный PowerShell/Python.
- Активный проект изменяется только скриптом.
- Отчёт всегда создаётся в `C:\Users\Dmitrii\ProFutbik\reports`.
- В консоли желательно показывать только понятные stage-строки, `DONE`, `EXIT_CODE`, `REPORT`.
- Не открывать браузер автоматически.
- Не требовать Y/N.
- Не оставлять пакетные BAT и временные служебные файлы в активном Hugo-проекте.

## Инструкция пользователю всегда должна говорить

- какое окно запустить;
- какое окно оставить открытым;
- какое окно закрыть после `DONE`;
- где найти report;
- какой именно файл прислать обратно.

## Безопасность

- Перед экспериментом — только точечный backup затрагиваемых файлов.
- При любой ошибке — автоматический rollback.
- Полный backup не делать перед каждой правкой.
- Полный backup делается после визуального подтверждения успешного блока или по отдельной просьбе пользователя.
- Не менять несвязанные файлы.
- Если предыдущий пакет не дал визуального изменения, не выдавать следующие пакеты вслепую: сначала читать report и диагностировать реальный source/runtime.

## Обмен результатами

Предпочтительно формировать компактный TXT report. Если TXT не загружается в чат, BAT должен дополнительно создавать ZIP, содержащий report и нужные диагностические файлы.
